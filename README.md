# NLP-Powered AI PDF Assistant

A beginner-friendly, local Retrieval-Augmented Generation (RAG) application. Upload text-based PDFs, ask questions in natural language, and receive answers grounded in passages from those PDFs, with filename and page references.

## Architecture

```text
PDF upload
   |
   v
PyPDF extracts text page by page
   |
   +--> spaCy sentence segmentation
   +--> NLTK tokenization, stop-word filtering, and lemmatization for analysis
   |
   v
Sentence-aware chunks (~500 characters, ~100 characters of overlap)
   |
   v
Sentence Transformers (all-MiniLM-L6-v2) creates embeddings
   |
   v
ChromaDB stores embeddings, original passage text, and PDF/page metadata

Question --> question embedding --> cosine-similarity search (top 3 passages)
                                         |
                                         v
                           Google Gemini API (cloud)
                                         |
                                         v
                         Answer and expandable sources
```

An **embedding** is a list of numbers that represents a piece of text. Texts with related meanings tend to have vectors near each other, so the system can find useful passages even when a question uses different wording. NLTK and spaCy analyses do not replace the PDF text: chunks sent to the embedding model and LLM keep the source wording (apart from whitespace normalization).

The answer prompt instructs Gemini to use only retrieved passages. If no passage meets the similarity threshold, the app says it could not find the information. The displayed source snippets and page numbers are read from ChromaDB metadata, not generated by the LLM.

## NLP techniques used

- **Whitespace cleanup and regular expressions:** make extracted PDF text easier to split and analyze without rewriting its words.
- **Sentence segmentation (spaCy):** identifies sentence boundaries so chunks are less likely to cut a thought in half.
- **Tokenization (NLTK):** separates text into words and punctuation for analysis.
- **Stop-word filtering:** excludes frequent words such as “the” and “is” from the analysis tokens. It is not applied to embedded passages.
- **Lemmatization:** reduces words to dictionary forms when the spaCy English model or NLTK WordNet data is installed. It is not applied to embedded passages.
- **Semantic embeddings:** represent the original chunks and questions as vectors for meaning-based retrieval.

If `en_core_web_sm` is not installed, spaCy's built-in English sentence segmenter is used. If WordNet is also unavailable, lemmatization falls back to the filtered tokens; the app remains usable.

## Technology stack

Python, Streamlit, PyPDF, NLTK, spaCy, Hugging Face Sentence Transformers, LangChain, ChromaDB, and Google's Gemini API. Gemini answer generation uses the free tier when available; Google applies usage limits, and terms or quotas can change. PDF extraction, embeddings, and ChromaDB remain local. The embedding model is downloaded from Hugging Face the first time it is used. Retrieved PDF passages are sent to Google's API to generate answers, so do not upload sensitive documents.

## Project structure

```text
Simple-RAG-NLP/
├── app.py                 # Streamlit interface, chat history, uploads, and source display
├── ingest.py              # PDF text extraction, chunking, deduplication, and Chroma indexing
├── nlp_preprocessing.py   # spaCy sentence segmentation and NLTK text analysis
├── embeddings.py           # Sentence Transformer setup and persistent ChromaDB connection
├── rag_pipeline.py         # Question search, evidence threshold, and Gemini answer generation
├── requirements.txt        # Python package dependencies
├── README.md               # Setup, architecture, usage, and troubleshooting
├── documents/              # Optional place to keep local PDF copies; uploads are not copied here
└── vectorstore/            # Persistent local ChromaDB data, created/updated by the app
```

Uploaded file bytes are processed in memory. The vector database stores extracted chunks and metadata so they remain available after restarting the app. To remove an indexed document, remove its entries from the local Chroma collection (or clear the local vector store and reprocess the PDFs). Do not commit private PDFs or vector-store data to source control.

## Installation on Windows

### 1. Install Python and VS Code

1. Install **Python 3.11** from [python.org](https://www.python.org/downloads/). Select **Add Python to PATH** during installation.
2. Install [Visual Studio Code](https://code.visualstudio.com/).
3. In VS Code, install the Microsoft **Python** extension and open this project folder.
4. Open a new PowerShell terminal in VS Code and verify Python:

   ```powershell
   py -3.11 --version
   ```

### 2. Create and activate a virtual environment

Run these commands from the project folder:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, allow local scripts for your user, then activate again:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
.\.venv\Scripts\Activate.ps1
```

When activation succeeds, `(.venv)` appears at the start of the terminal prompt. In VS Code, select `.venv\Scripts\python.exe` with **Python: Select Interpreter**.

### 3. Install Python dependencies

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

For richer spaCy sentence boundaries and lemmatization, install its small English model (optional):

```powershell
python -m spacy download en_core_web_sm
```

Without that model, the app uses spaCy's built-in sentence segmenter and remains functional.
If you also want WordNet lemmatization when the spaCy model is not installed, download its NLTK data:

```powershell
python -c "import nltk; nltk.download('wordnet')"
```

### 4. Get a Gemini API key

1. Create a Gemini API key in [Google AI Studio](https://aistudio.google.com/apikey).
2. Open the `.env` file in the project folder and replace `PASTE_YOUR_GEMINI_API_KEY_HERE` with your key.

   The `.env` file is excluded from Git. Keep your key private and do not share or commit it.

   If `.env` is missing, create a file named `.env` in the same folder as `app.py` with this line:

   ```text
   GOOGLE_API_KEY=your-real-key-here
   ```

### 5. Run the application

With the virtual environment active and the API key saved in `.env`:

```powershell
streamlit run app.py
```

Streamlit opens the app in your browser. The first run downloads the embedding model, which may take a few minutes. Embeddings and the Chroma index are reused on later runs. Answer generation requires an internet connection and uses Google's Gemini API.

## How to use it

1. In the sidebar, select one or more text-based PDF files.
2. Select **Process documents** and wait for the extraction and indexing confirmation.
3. Ask a question in the chat box.
4. Read the answer and expand each **Source** section to inspect its PDF filename, page number, and retrieved text.
5. Select **Clear chat** to clear conversation history; indexed documents stay in the local vector store.

Example questions:

- “What is the main purpose of this document?”
- “Explain the steps described for data collection.”
- “How do the two approaches differ?”
- “What date or amount is stated in the report?”
- “Which risks does the document identify?”

For multiple PDFs, process all selected files together. Reprocessing an unchanged file with the same filename is skipped. Uploading changed content under that filename replaces its older indexed chunks.

## Test each component

Run these from the activated virtual environment in the project directory:

1. **Preprocessing and NLP**

   ```powershell
   python -c "from nlp_preprocessing import preprocess_text; result = preprocess_text('The teams are running useful tests.'); print(result)"
   ```

   Check that sentences, tokens, filtered tokens, and lemmatized tokens are returned. The original input is not modified.

2. **Chunking**

   ```powershell
   python -c "from ingest import chunk_sentences; chunks = chunk_sentences(['First sentence. ' * 35, 'A second sentence.']); print([(len(chunk), chunk[:60]) for chunk in chunks])"
   ```

   Check that chunks are no longer than 500 characters and that adjacent chunks share a short overlap when possible.

3. **PDF extraction and ingestion**

   Upload a small text-based PDF in the app and select **Process documents**. Confirm that the success message reports indexed chunks. A scanned image-only PDF should produce a “no extractable text” message instead of silently appearing indexed.

4. **Embeddings and persistent ChromaDB**

   After processing a PDF, run:

   ```powershell
   python -c "from embeddings import create_vector_store; store = create_vector_store(); print('Indexed chunks:', len(store.get(include=['metadatas'])['ids']))"
   ```

   Run it again after restarting the app; the indexed chunk count should remain.

5. **Retrieval and answer generation**

   Ask a question that is answered in the PDF. Confirm that relevant passages and real page metadata appear under **Sources**. Then ask for information clearly absent from the PDFs and confirm the assistant reports that it could not find the answer.

## Troubleshooting

- **`py` or `python` is not recognized:** reinstall Python and select **Add Python to PATH**, then reopen the VS Code terminal.
- **PowerShell says script execution is disabled:** use the `Set-ExecutionPolicy ... -Scope CurrentUser` command in the environment setup section.
- **`ModuleNotFoundError`:** activate `.venv` in the same terminal and rerun `python -m pip install -r requirements.txt`. In VS Code, make sure `.venv\Scripts\python.exe` is selected.
- **Gemini API key error:** set `GOOGLE_API_KEY` in the same PowerShell terminal before running Streamlit. Create or view a key in [Google AI Studio](https://aistudio.google.com/apikey).
- **Gemini quota or connection error:** check your internet connection and the current [Gemini API pricing and limits](https://ai.google.dev/gemini-api/docs/pricing). Free-tier access has usage limits and may not be available in every region.
- **First launch is slow or runs out of memory:** the embedding model is downloaded and loaded locally. Close other memory-heavy apps and retry; CPU inference is configured for compatibility.
- **No text found in a PDF:** it may contain scanned page images. Run OCR with a trusted OCR tool first, then upload the resulting searchable PDF.
- **Password-protected PDF:** remove the password before upload. Only PDFs that can be opened without a password are supported.
- **Answer says the information was not found:** verify that the PDF was processed, that the answer is present in selectable PDF text, and that your question uses related terms. Similarity scores are a retrieval aid, not a guarantee; adjust `MIN_RELEVANCE_SCORE` in `rag_pipeline.py` cautiously if your documents need different sensitivity.
- **Wrong or missing source page:** confirm the PDF's text extracts correctly. Page numbers refer to the PDF's 1-based page order.
- **Clear chat did not remove documents:** this is intentional. Chat history and the persistent Chroma index are separate; clearing chat does not delete indexed PDF content.
